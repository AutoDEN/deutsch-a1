# Немецкий для жизни A1 — сборка курса в один сайт

Рабочая инструкция по проекту: что уже сделано, откуда берётся материал,
по каким правилам собирается урок и что делать дальше.

---

## 1. Что это

Курс «Немецкий для жизни A1» лежал на диске 36 отдельными папками — экспорт
с платформы, где каждый урок это самостоятельный `lesson.html` с чёрным фоном,
своей копией стилей и скриптов. Задача: собрать всё в один сайт с общим
оформлением, сквозной навигацией и потом поднять его на VPS.

Эталон оформления — новая версия первого урока, опубликованная автором:
`https://erosheve.ru/a1-urok-1/`. Описание того, как устроен урок и курс:
`https://erosheve.ru/a1-info/`.

Исходные папки лежат рядом, на уровень выше (`../01 …` … `../36 …`), и
**не изменяются** — это архив, из которого мы читаем.

    vocab.json                словарь урока (22 слова)

    tts/diktat.json           сценарий озвучки диктанта

Видео **не копируется**, а прилинковано жёсткой ссылкой (`New-Item -ItemType
HardLink` в PowerShell) на файл в исходной папке — тот же том, ноль лишнего
места. Аудио копируется, оно мелкое.

Сейчас сайт занимает около 800 МБ, из них ~723 МБ — пять видео по жёсткой
ссылке (уроки 2 и 3 плюс три видео подготовительных уроков), ещё 72 МБ — аудио:
30 диалогов курса, 30 диктантов, озвучка таблицы звуков и 464 слова для колоды.

## 3. Нумерация уроков

Одна папка на диске ≠ один урок. У первых трёх уроков материалы и грамматика
лежат отдельными папками, причём папка «05 Урок 2 (грамматика)» вложена внутрь
папки урока 2. `build.py` сводит половинки и делает нумерацию сквозной:

| Урок | Из каких папок |
|---|---|
| Подготовительный 1–2 | 01, 02 |
| Урок 1. Приветствие | 03 (грамматика) + 04 (материалы) |
| Урок 2. Представьтесь | 05 (грамматика) + 06 (материалы) |
| Урок 3. Откуда Вы | 07 (грамматика) + 08 (материалы) |
| Уроки 4–30 | по одной папке (09 … 35) |

Папка 36 (бонусные карточки Anki к сериалу Nicos Weg) в сборку не входит:
владелец попросил её не делать и убрать из списка на главной.

Итого 33 позиции: 2 подготовительных урока, справочник по транскрипции
и 30 уроков. Слаги — латиницей по теме: `01-begruessung`, `02-vorstellung`,
`03-herkunft`, `04-wie-geht-es`, `05-zahlen-0-10`, дальше по таблице `SLUGS`
в `build.py`.

## 4. Договорённости с владельцем (важно, не нарушать)

1. **Ничего не выдумывать.** Содержание берётся только из материалов курса.
   Новые упражнения собираются из фраз, которые уже есть в диалогах и таблицах
   этого урока, — не из головы.
2. **22 слова в словаре каждого урока** — так устроен курс у автора.
   В исходных материалах их 9–10, остальные добираются из колоды по частотности.
3. **Ни одно слово не разбирается дважды.** Перед сборкой словаря проверяются
   словари всех готовых уроков плюс пассивный список урока 1.
4. **Транскрипция только проверенная.** Для слов из колоды берётся из неё же
   (и сверяется при каждой сборке). Для остальных — стандартная словарная
   нотация Duden, единая с колодой: `aɪ̯ ɔɪ̯ aʊ̯`, слоговые `n̩`, аффриката `t͡s`.
5. **Номера частотности не выдумываются.** Есть слово в колоде — ставим её номер.
   Нет — пишем «вне первых 300». Предлоги, артикли, местоимения — «служеб.».
6. **Раздел «Где это встретится на экзамене» удалён** по решению владельца
   (в `import_lesson1.py` это делает `cut_exam_section`). Упоминания формата telc
   внутри самих упражнений остаются — они часть условия задания.
7. **Диктанты озвучиваются синтезом** — качество владелец послушал и одобрил.

### Транскрипция: откуда берётся и как проверяется

Правило одно: **транскрипцию не сочиняем**. Для слов из первых 300 её берём
из колоды (`data/frequency-300.json`), и `render_vocab.py` при каждой сборке
сверяет её посимвольно — расхождение печатается в отчёте. Для слов вне колоды
транскрипция пишется по правилам из подготовительного урока 1: оглушение
конечных b/d/g, `-er` → [ɐ], `-en` → [n̩], `au/eu/ei` → [aʊ̯ ɔɪ̯ aɪ̯], `z` → [t͡s].

Проверить весь сайт разом (660 слов):

```bash
python tools/render_vocab.py       # сверка с колодой + поиск дублей
python tools/check_ipa.py          # полная проверка транскрипции
```

`check_ipa.py` работает в два прохода. Слова из первых 300 сверяются с колодой
посимвольно. Остальные 458 проверяются правилами чтения: «в написании есть sch —
в транскрипции обязан быть [ʃ]», «две согласные после гласной — значит краткая,
без [ː]», «конечное -b оглушается в [p]», «ровно одно основное ударение» и так
далее — всего два десятка связок плюс сверка числа слогов.

Правила не доказывают, что транскрипция верна, но ловят то, что рука набирает
неправильно: забытую долготу, пропущенный умлаут, лишнее ударение, «ц» без дуги.
Слова, к которым правило неприменимо, перечислены в словаре `EXCEPTIONS` внутри
скрипта — с объяснением, почему (`bisschen` — это `biss|chen`, а не `sch`).

Урок 1 пришёл с сайта автора, и в нём **10 слов было без транскрипции**:
шесть из них (gut, machen, heute, Arbeit, arbeiten, kommen) взяты из колоды,
четыре (danke, Erfolg, bald, Auf Wiederhören) в колоду не входят и записаны
по правилам выше.

Два известных и осознанных отклонения:

- `aussehen` в колоде записано как [ˈaʊ̯sˌz̥eːən] — с кружком оглушения под z.
  Это авторская запись, оставлена как есть.
- U+0067 «g» и U+0261 «ɡ» — один звук; в колоде встречаются оба, на страницах
  везде знак МФА, поэтому `same_ipa()` сравнивает их как одинаковые.

## 5а. Вторая колода Anki

Колода курса — 300 самых частотных слов, и в словарях уроков их всего 197.
Остальные 464 слова тематические, учить их тоже надо, поэтому они собраны
в отдельную колоду: `data/anki/woerter-der-lektionen.apkg` — 5,1 МБ, почти всё
это озвучка (сами карточки весят 80 КБ). Ссылка на неё есть в разделе
«Материалы» на главной странице сайта.

Как она устроена:

- **тип заметки скопирован из колоды курса** — те же 11 полей, тот же шаблон
  карточки, тот же CSS. Отличается только имя (`Нем-слова · уроки курса`) и id,
  чтобы импорт не тронул исходный тип заметки;
- **первым полем идёт `german`, а не `rank`.** Это единственное отклонение от
  исходного типа заметки, и оно вынужденное: Anki считает первое поле
  обязательным и при «Инструменты → Проверить базу данных» **молча удаляет**
  заметки с пустым первым полем. У 457 наших слов номера нет, так что колода
  развалилась бы при первой же проверке базы. На вид карточки это не влияет:
  шаблон обращается к полям по имени, меняется только порядок строк в редакторе;
- **номер в частотном списке ставится только авторский.** У большинства слов
  его нет — тогда поле пустое и жёлтый бейдж на карточке не появляется.
  Исключение: несколько слов урока 1, у которых номер есть, но за пределами
  первых 300 (danke — 773, tschüss — 3632). Своих номеров мы не выдумываем;
- **теги** — номер урока (`урок-14`) и `вне-первых-300`, так что колоду можно
  учить по урокам: в Anki фильтр `tag:урок-14`;
- **озвучка своя**: к каждому слову приложен mp3 примерно на полторы секунды —
  само слово с артиклем («der Wochenmarkt», «werfen», «bunt»), как в колоде
  курса, где к слову приложен opus такой же длины. Голос синтезированный, тот
  же, что читает диктанты. Файлы лежат в `data/anki/audio/`, в `.apkg` попадают
  вместе с базой;
- **поле german_rektion пустое** — данных об управлении глаголов у нас нет.
  Пояснения из словаря урока (раздел «note») в колоду не переносятся: для них
  в шаблоне нет своего поля, а сваливать их в чужое — врать структурой.

Пересобрать целиком:

```bash
python tools/tts_words.py     # озвучка слов, ~4 минуты на 464 слова
python tools/make_anki.py     # сборка .apkg вместе с озвучкой
python tools/check_anki.py    # проверка правилами Anki
```

`tts_words.py` считает имя файла из слова и урока, а не из его номера в списке:
если словарь изменится, уже записанные файлы останутся на своих местах, и
скрипт допишет только новые. Если у слова файла нет, поле `audio` остаётся
пустым — на карточке просто не будет кнопки воспроизведения.

Про сборку: `python tools/make_anki.py`. Скрипт читает готовые страницы уроков
(а не `vocab.json`, потому что у урока 1 его нет) и собирает `.apkg` целиком —
это zip с SQLite-базой схемы 11.

### Как проверяется колода

Запустить Anki из-под нашего Python нельзя: в комплекте Anki 26.5 идёт своя
сборка под Python 3.13 (модуль `_rsbridge` скомпилирован под неё), а в системе
стоит 3.14. Поэтому проверка своя — `tools/check_anki.py` повторяет правила,
по которым Anki сам разбирает колоду:

```bash
python tools/check_anki.py                                  # наша колода
python tools/check_anki.py ../nem-slova-4500-free-preview-300.apkg   # колода курса
```

Замечания делятся на две группы. **Ошибки** — то, из-за чего Anki сломается или
потеряет данные (пустое первое поле, битые ссылки заметка → тип, карточка →
колода, поле в шаблоне, которого нет). **Замечания** — то, что Anki чинит сам
(контрольные суммы, позиции новых карточек).

Инструмент откалиброван по колоде курса: она проходит проверку без ошибок —
значит, правила не строже, чем сам Anki. Проверять её полезно и как эталон:
если наша колода ведёт себя так же, как заведомо рабочая, — всё в порядке.

Отдельно проверяется рендеринг: шаблон карточки прогоняется по всем 464
заметкам, и ни в одной не должно остаться неподставленных `{{поле}}`.

## 6. Как собран урок (структура страницы)

Порядок разделов одинаковый во всех уроках:

1. `<header class="magnet-hero">` — h1 и лид-абзац. Лид берётся из вступления
   к грамматике урока, если оно есть; иначе пишется из темы урока.
2. **Диалоги урока** — плеер `media/dialoge.mp3` и тексты диалогов.
3. **Словарь урока** — между маркерами `<!-- vocab:start -->` и `<!-- vocab:end -->`,
   генерируется из `vocab.json`.
4. **Выучить наизусть** — 8–14 фраз из материалов: слева немецкий со звуком
   и транскрипцией, справа перевод, разбор под переводом закрыт. Генерируется
   между маркерами `<!-- merken:start -->` и `<!-- merken:end -->`: раздел 6а.
5. **Грамматика** — видео (если есть), дальше нумерованные разделы `h3`.
   Если у урока была отдельная папка с грамматикой, её текст сводится сюда же.
6. **Упражнения** — сначала родные из материалов, затем добавленные:
   диктант на слух, письмо с образцом, говорение с образцом.
7. `<nav class="lesson-nav">` — проставляется автоматически, руками не трогать.

Классы оформления: `.note` (жёлтая врезка — ловушка, разбор), `.sample`
(зелёная врезка — образец для самопроверки), `.hl` (подсветка слова),
`.voc*` (словарь), `.m/.f/.n` (артикль цветом: der синий, die красный, das зелёный).

### Синтаксис упражнений

- `((ответ::подсказка))` — поле для вписывания, подсказка необязательна;
- `{{верный|вариант|вариант::подсказка}}` — выпадающий список, правильный
  пишется первым, порядок в списке тасуется стабильно.

Внутри ответа не должно быть `:` и `)` — их не переваривает регулярка движка.

## 6а. Фразы наизусть: звук, транскрипция, разбор

Сделано во всех тридцати уроках: 320 фраз наизусть с озвучкой, транскрипцией
и разбором плюс 90 сценок к устным заданиям — 410 файлов, 15 МБ.

**Вид блока переделан по просьбе владельца** (было: таблица «русский —
немецкий», как в материалах курса). Сейчас так: слева немецкая фраза с кнопкой
звука и транскрипцией, справа перевод, под переводом — разбор, что здесь можно
произнести неправильно и почему. Немецкий стоит первым намеренно: строку можно
пройти как проверку себя, а не как чтение готового перевода. Русского «примерно
как по-русски» на странице по-прежнему нет — только транскрипция, это отдельная
просьба владельца.

**Разбор закрыт и открывается щелчком** по строке «разбор произношения»:
сначала вспомнить и сверить со звуком, и только потом читать объяснение.
Открытым он занимал половину блока и превращал список в чтение.

Вёрстка — сетка в две колонки (`.ph-item`), а не таблица. У фразы бывает
несколько реплик — в уроке 1 это обмен репликами, — и в сетке каждая встаёт
ровно напротив своего перевода. В таблице так не получалось: с кнопкой звука
у каждой реплики строки разъезжались по высоте. На экране уже 560 px колонки
складываются в одну, перевод и разбор уходят под фразу.

**Одна фраза — одна запись.** Кнопки «прослушать всё подряд» здесь нет:
в этом разделе не диалог, а список фраз на память, и слушать их подряд незачем.

Тот же звук добавлен в образец к последнему упражнению (говорение), но там
наоборот: **сценка озвучена целиком, обе роли в одном файле**. Сценок столько
же, сколько в задании ситуаций, — резать их по репликам нечего, это цельный
кусок речи. Разбора там нет: задание на речь, а не на чтение транскрипции.

### Откуда что берётся

Всё лежит в `lessons/<слаг>/phrases.json`: группы фраз, в группе реплики.

```json
{ "groups": [ {
  "id": "merken",              // он же имя маркеров в index.html
  "layout": "columns",         // "columns" — фразы с разбором, "sample" — врезка,
                               // "qa" — «вопрос — ответ» в контрольной
  "join": false,               // true — все реплики одним файлом (сценки)
  "intro": ["абзац перед списком фраз", "…"],
  "items": [ {
    "id": "01",
    "lines": [ {
      "voice": "lena",                       // голос из VOICES в tools/tts.py
      "de": "Hallo Clara! Wie geht's?",
      "speak": "…",                          // что произносить, если не "de"
      "ipa": "haˈloː ˈklaːʁa · viː ɡeːt͡s",   // без квадратных скобок
      "ru": "Привет, Клара! Как дела?"
    } ],
    "tip": "Разбор: что здесь звучит не так, как пишется."
  } ]
} ] }
```

У группы `"layout": "qa"` вместо `tip` и `ipa` работает поле `task` — задание
по-русски, о чём спросить; первая реплика item'а считается вопросом, вторая
образцом ответа, и озвучены они по отдельности (`"join"` не ставится).

Сборка в два шага, порядок важен — имена mp3 считаются из текста реплики,
поэтому сначала озвучка, потом вёрстка:

```bash
python tools/tts_phrases.py 01-begruessung      # записи
python tools/render_phrases.py 01-begruessung   # блоки между маркерами
```

### Про темп: почему синтез кажется медленным

Первая версия звучала заметно медленнее диалогов урока, и дело было не в
скорости речи. Замедление `rate` убрано совсем — темп у голоса обычный.
Тянул паузы сам синтез: после восклицательного знака он делает больше секунды
тишины, плюс по секунде с краёв записи.

Мерка — авторский `dialoge.mp3`: там реплика «Hallo Lena! Danke, gut. Und dir?»
занимает 3,55 с, пауза внутри неё — треть секунды. Наша та же реплика после
обрезки — 3,27 с. Делает это `TRIM` в `tts_phrases.py`: тишина с краёв режется
до 50 мс, внутренние паузы подрезаются до `PAUSE_MAX` (0,35 с). В склеенной
сценке между ролями ставится `PAUSE` (0,6 с) — смена говорящего должна быть
слышна.

### Правила этой части

1. **Транскрипция здесь фразовая, а не словарная.** В речи слова склеиваются:
   `wie geht's` — это [viː ɡeːt͡s], где `t` и `s` дают один звук, и по отдельным
   словарным записям этого не увидеть. Знаки те же, что в словарях уроков
   (нотация Duden), и `check_ipa.py` эту часть не проверяет — он смотрит
   только словарь (`voc-ipa`), так что за фразы отвечает тот, кто их пишет.
2. **Разбор — только про звук и форму этой фразы.** Не пересказ грамматики
   урока: почему `Gute Nacht` без `-n`, почему `-er` звучит как «а», где
   оглушается `d`. Одна-две мысли, не больше трёх.
3. **Имя mp3 содержит хвост от текста реплики.** Поправили текст — при
   следующем прогоне запишется новый файл, а осиротевший старый скрипт
   удалит сам. Так запись не разъезжается с текстом молча.
4. **Фразы-заготовки озвучиваются договорёнными.** В уроке 3 половина списка —
   шаблоны с пропуском (`Ich komme aus…`, `Ich wohne in…`). Многоточие вслух
   не произнесёшь, поэтому в поле `speak` лежит та же фраза с городом для
   примера, а на странице остаётся исходная, с многоточием. Что запись
   договорена, сказано один раз во вступлении к списку — не в каждом разборе.

### Что важно помнить про урок 1

`tools/import_lesson1.py` собирает страницу урока 1 заново из снимка сайта
автора — и вместе со всей страницей затрёт и маркеры, и блок фраз.
Инструмент разовый, запускать его теперь незачем; если всё же понадобится,
маркеры `<!-- merken:start/end -->` и `<!-- sprechen:start/end -->` придётся
расставить заново, а потом прогнать `render_phrases.py`.

## 6б. Контрольные работы

После каждого пятого урока в списке курса стоит отдельная страница —
контрольная за эти пять уроков. Не хвост урока, а своя позиция со своим слагом
и сквозной навигацией: урок остаётся уроком, а контрольную можно пройти
повторно, не листая чужую страницу.

| Контрольная | Уроки | Слаг |
|---|---|---|
| 1 | 1–5 | `test-1-lektionen-1-5` |
| 2 | 6–10 | `test-2-lektionen-6-10` |
| 3 | 11–15 | `test-3-lektionen-11-15` |
| 4 | 16–20 | `test-4-lektionen-16-20` |
| 5 | 21–25 | `test-5-lektionen-21-25` |
| 6 | 26–30 | `test-6-lektionen-26-30` |

Все шесть описаны в `TESTS` в `build.py` (`n`, `after` — номер урока, за которым
контрольная встаёт, `title`, `slug`) и все шесть собраны. Новый вид позиции —
`kind: 'test'`, подписи для него добавлены в `label_of` и `nav_label`, в списке
на главной он идёт вместе с уроками и помечен тегом «контрольная».

Каждая устроена одинаково: 38 проверяемых пропусков (8 на слух, 9 на чтение,
21 на письмо) плюс устная часть — десять пар «вопрос — ответ» и три ситуации.
Звука на контрольную 24 файла: сцена для аудирования на полторы-две минуты,
20 записей к вопросам и ответам и три сценки; 2,1–2,5 МБ. Устная часть в счёт
не идёт: её проверяет только сам студент.

Со второй контрольной добавляется **«Wiederholung — короткое повторение»**:
письменный блок между письменной и устной частями, по два-три пункта на каждую
**пройденную раньше** пятёрку. Он намеренно маленький — основная часть остаётся
своей пятёркой, а каждую прошлую студент уже сдавал в её собственной
контрольной; здесь только проверка, что не выветрилось.

| Контрольная | Повторение | Всего пропусков | Порог (60 %) |
|---|---|---|---|
| 1 | — | 38 | 23 |
| 2 | 6 (уроки 1–5) | 44 | 26 |
| 3 | 6 (1–5, 6–10) | 44 | 26 |
| 4 | 6 (1–5, 6–10, 11–15) | 44 | 26 |
| 5 | 8 (четыре пятёрки) | 46 | 28 |
| 6 | 10 (пять пятёрок) | 48 | 29 |

### Из чего состоит

Четыре части, порядок как на экзамене:

1. **Teil 1. Hören** — запись `media/hoeren.mp3`: три коротких сцены за пять
   уроков, между сценами пауза подлиннее. Задания — `richtig/falsch` и числа
   на слух. **Текста сцен на странице нет**, он спрятан под `<details
   class="script">`: с открытым текстом это уже не задание на слух.
2. **Teil 2. Lesen** — короткий текст во врезке `.sample`, собранный из реплик
   тех же уроков, дальше `richtig/falsch` и выбор ответа.
3. **Teil 3. Schreiben** — анкета по тексту, формы глаголов, `du` или `Sie`,
   порядок слов в вопросе. Порядок слов сделан **выбором**, а не вписыванием:
   движок сверяет строку целиком и свободный ответ принять не может.
4. **Wiederholung** (со второй контрольной) — короткий письменный блок по
   прошлым пятёркам, по два-три пункта на каждую. Идёт после письменной части,
   перед устной, и сдвигает нумерацию устных заданий на единицу.
5. **Teil 4. Sprechen** — два задания. Первое, «вопрос — ответ»: десять
   заданий по-русски («спросите, откуда человек»), немецкий вопрос и образец
   ответа закрыты и озвучены по отдельности. Список проходится дважды: сначала
   спрашиваешь сам и сверяешься с записью, потом включаешь запись вопроса
   и отвечаешь на неё вслух. Второе — три ситуации, к каждой образец во врезке
   `.sample` с озвучкой целой сценки. И там и там эхо-метод: сначала сказать
   самому, потом включить образец и повторить за диктором. Микрофона
   и распознавания речи нет — и не надо: на A1 распознавание врёт чаще,
   чем помогает.

В конце — таблица, куда записать результат каждой части, порог (60 % от суммы,
см. таблицу выше) и список, к какому уроку возвращаться по каждому виду ошибки. Общего счёта
по странице движок не ведёт, счёт идёт внутри каждого задания.

### Как собирается

```bash
python tools/tts.py lessons/<слаг>/tts/hoeren.json lessons/<слаг>/media/hoeren.mp3
python tools/tts_phrases.py <слаг>        # сценки к говорению, "join": true
python tools/render_phrases.py <слаг>     # между <!-- sprechen:start/end -->
python tools/check_test.py <слаг>         # ни одного слова вне охваченных уроков
python build.py                           # список и навигация
```

Файлы контрольной: `index.html`, `phrases.json` (группы `qa` и `sprechen`),
`tts/hoeren.json`, `media/`. Словаря `vocab.json` у контрольной нет и быть
не должно: новых слов она не вводит.

### Правила этой части

1. **Ничего нового.** Ни одного слова, которого студент ещё не видел, — это та
   же договорённость §4.1, только проверить её тут труднее: пять уроков сразу,
   и «правильная» немецкая фраза легко утаскивает незнакомое слово. Поэтому есть
   `check_test.py`: он берёт все немецкие слова со страницы и из озвучки и
   сверяет со словарём **всех пройденных** уроков — с первого по тот, за которым
   стоит контрольная. Тема контрольной — последняя пятёрка, но язык накопительный:
   `Ich heiße` во второй контрольной законно, хотя разбиралось в уроке 2. Пусто
   на выходе — чисто.
2. **Форма слова тоже считается новой.** Скрипт ловил это трижды: `arbeitet`
   (глагол `arbeiten` в уроках есть, а третьего лица студент не видел),
   `Arzthelferin` (в уроке 16 роль названа `Arzthelfer`), `feiert` (в уроке 29
   только `feiern` и `Ich feiere`). Такие места переписываются — `Clara sagt:
   „Ich arbeite …“`, женский голос меняется на мужской вместе с подписью роли, —
   а не добавляются в исключения. В `SERVICE` лежит только язык самого бланка:
   `Teil`, `Aufgabe`, `richtig`, `falsch`.
3. **Задание на слух не дублируется текстом.** Расшифровка — под `<details>`,
   и в инструкции прямо сказано открывать её только после проверки.
4. **Реплики берутся целиком.** Сцены собираются из готовых фраз уроков, а не
   переписываются «под задание»: иначе на слух звучит не то, что учили.

## 7. Как делать следующий урок

Пример для урока 6 (папка `../11 Урок 6 - Да, Нет, Спасибо, Пожалуйста_`,
слаг `06-ja-nein-danke`).

**Шаг 1. Прочитать материалы.** Снять теги с `lesson.html` исходной папки и
прочитать целиком: диалоги, словарь, фразы наизусть, грамматику, упражнения.
Если у урока есть вторая папка с грамматикой — прочитать и её.

**Шаг 2. Перенести медиа.**

```bash
mkdir -p site/lessons/06-ja-nein-danke/{media,tts}
cp "../11 Урок 6 …/audio-0.mp3" site/lessons/06-ja-nein-danke/media/dialoge.mp3
# видео, если есть, — жёсткой ссылкой через PowerShell New-Item -ItemType HardLink
```

**Шаг 3. Подобрать 22 слова.** Прогнать текст урока через колоду: взять слова
из `data/frequency-300.json`, которые встречаются в уроке, выбросить всё, что
уже разобрано в готовых уроках и в пассивном списке урока 1, отсортировать по
рангу. Взять слова из словаря исходных материалов плюс самые частотные из
оставшихся — так, чтобы вышло ровно 22 и чтобы они были из диалогов, а не из
грамматических таблиц.

**Шаг 4. Написать `vocab.json`.** Поля:

```json
{
  "lemma": "helfen",            // для существительных без артикля
  "gender": "der",              // артикль, только у существительных
  "rank": 258,                  // номер из колоды; нет слова в колоде — поля нет
  "service": true,              // вместо ранга напишет «служеб.» (предлоги и т.п.)
  "ipa": "ˈhɛlfn̩",             // без квадратных скобок
  "forms": "half · hat geholfen",
  "ru": "помогать",
  "ex": "Kann ich Ihnen helfen?",       // фраза из этого урока
  "ex_ru": "Могу я Вам помочь?",
  "note": "Кому помогают — в Dativ."    // необязательно
}
```

**Шаг 5. Собрать страницу** по структуре из раздела 6. В месте словаря
поставить пустые маркеры `<!-- vocab:start -->` / `<!-- vocab:end -->`.
Дописать три упражнения: диктант, письмо и говорение с образцами.

**Шаг 6. Диктант.** Текст — пересказ диалогов урока, обычно в третьем лице,
с прицелом на грамматику этого урока. 12–14 пропусков по 2–4 слова.
Сценарий кладётся в `tts/diktat.json`:

```json
{ "rate": "-5%", "pause": 0,
  "lines": [ { "voice": "erzaehler", "text": "…" } ] }
```

Голоса: `lena`, `clara`, `max`, `mueller`, `erzaehler` (см. `VOICES` в `tts.py`).
Для диктанта — один рассказчик; для озвучки по ролям — реплики разными голосами
с паузой `0.45`.

**Шаг 7. Собрать и проверить.**

```bash
cd site
python tools/tts.py lessons/06-ja-nein-danke/tts/diktat.json lessons/06-ja-nein-danke/media/diktat.mp3
python tools/render_vocab.py 06-ja-nein-danke     # печатает расхождения с колодой
python build.py                                   # манифест, список, навигация
```

Затем открыть страницу в браузере и прогнать все упражнения скриптом: подставить
правильные ответы из `window.fillBlanksData` и нажать проверку — должно быть
«столько же из стольких же» в каждом блоке. Заодно проверить, что на странице не
осталось необработанных `((` или `{{`.

**Шаг 8. Фразы наизусть с озвучкой.** Написать `phrases.json` (фразы с
транскрипцией и разбором плюс сценки к устному заданию, группа сценок —
с `"join": true`), расставить маркеры `<!-- merken:start/end -->` вместо
списка фраз и `<!-- sprechen:start/end -->` вместо образца, подключить
`shared/phrase-audio.js` рядом с `fillblanks.js`, прогнать `tts_phrases.py`
и `render_phrases.py`. Подробно — в разделе 6а.

## 8. Инструменты

| Команда | Что делает |

| `python tools/deploy.py "сообщение"` | пересоберёт сайт и выкатит его на GitHub Pages (без сообщения — дата и время) |

| `python tools/render_vocab.py [слаг …]` | соберёт словарь из `vocab.json` и сверит номера, транскрипцию и род с колодой |
| `python tools/check_ipa.py` | проверит транскрипцию всех 660 слов: сверка с колодой + правила чтения |
| `python tools/check_test.py [слаг …]` | проверит контрольную: нет ли в ней слова, которого не было в её пяти уроках |
| `python tools/tts_phrases.py [слаг …]` | озвучит фразы из `phrases.json` (докачивает, лишние файлы удаляет) |
| `python tools/render_phrases.py [слаг …]` | соберёт блоки озвученных фраз и вставит их в страницу урока |
| `python tools/tts_words.py` | озвучит слова второй колоды (докачивает: уже записанные пропускает) |
| `python tools/make_anki.py` | пересоберёт вторую колоду Anki из словарей уроков |

| `python tools/tts.py сценарий.json выход.mp3` | озвучит сценарий |
| `python tools/import_lesson1.py` | пересоберёт урок 1 из снимка страницы автора |
| `python -m http.server 8765 --bind 127.0.0.1` | локальный просмотр на http://127.0.0.1:8765 |

**Пауза в сценариях `tts.py` задаётся в секундах.** `"pause": 0.7` — это семьсот
миллисекунд; `"pause": 700` даст почти двенадцать минут тишины после каждой
реплики (проверено: файл на 371 МБ вместо двух).

Зависимости: Python 3, `edge-tts` (`pip install --user edge-tts`), `ffmpeg`
(лежит в `C:\yt-dlp\ffmpeg`). Интернет нужен только для озвучки.

После правки `shared/lesson.css` в браузере жать **Ctrl+Shift+R** — иначе
отдаётся старая версия из кеша.

## 9. Навигация

Стрелки внизу урока проставляет `build.py`, руками их править бессмысленно —
перезапишет. Логика: стрелка ведёт к ближайшему **готовому** уроку в эту сторону,

показывается серая подпись соседа по порядку.

## 10. Онлайн-версия (GitHub Pages)

Сайт лежит онлайн на GitHub Pages. **Репозиторий — сама папка `site/`**:
то, что вы правите локально, и есть то, что публикуется, отдельной «сборки
для прода» нет. Исходные папки курса (`../01 Подготовительный…`) в репозиторий
не входят — это архив на 700+ МБ, он остаётся только на диске.

**Выкатка одной командой** из папки `site`:

```
python tools/deploy.py "правки урока 7"
```

Скрипт пересоберёт манифест и навигацию (`build.py`), закоммитит изменения и
отправит их на GitHub. Pages пересобирает сайт сам — изменения видны онлайн
через 30–60 секунд. Если менять нечего, скрипт так и скажет и ничего не сделает.

### Чего в онлайн-версии нет

| Что | Почему | Что видно вместо |
|---|---|---|
| пять видео | 127–153 МБ каждое, у GitHub жёсткий лимит **100 МБ на файл** | заглушка на месте плеера |
| две колоды `.apkg` | решение владельца — онлайн не публикуем | заглушка вместо кнопки скачивания |

Оба исключения прописаны в `.gitignore` (`*.mp4`, `*.apkg`). Локально файлы
на месте и работают как раньше.

### Как устроена заглушка

Разметка **одна на обе версии** — иначе каждая пересборка расходилась бы с
тем, что лежит в репозитории. Разницу прячет `shared/offline-assets.js`:

- **видео** — обработчик `error` на каждом `<source>`. Файл не загрузился —
  `<video>` заменяется абзацем `.asset-missing`. Работает и на `file://`,
  и по http; локально файл на месте, обработчик молчит.
- **колоды** — элемент с атрибутом `data-local-only` заменяется той же
  заглушкой, **только если хост оканчивается на `github.io`**. Проверка идёт
  по имени хоста, а не запросом к серверу: `fetch` на `file://` блокируется
  CORS и давал бы ложное срабатывание. Локальный просмотр через
  `python -m http.server` тоже показывает колоды — хост там `127.0.0.1`.

Скрипт подключён только там, где есть что прятать: уроки 1, 2, 3,
подготовительные 1–2 и главная. Метка `data-local-only` на главной ставится
в `build.py` (функция `materials()`), а не руками в `index.html`, — иначе
ближайшая пересборка её затрёт.

Побочный эффект: если запустить `build.py` на свежем клоне, где `.apkg` нет,
`materials()` уберёт с главной весь блок «Материалы». На рабочей машине файл
на месте, так что в обычном цикле это не мешает.

### Прочее

- `.nojekyll` отключает обработку Jekyll — иначе он игнорирует пути с
  подчёркиванием и замедляет деплой.
- `.gitattributes` (`* -text`) запрещает git подменять переводы строк:
  страницы уроков в CRLF, часть скриптов в LF, и трогать это незачем.
- Сайт **публичный** — на бесплатном аккаунте GitHub Pages иначе не умеет.
  `<meta name="robots" content="noindex, nofollow">` держит его вне поиска,
  но это не защита. План с VPS (раздел 11) остаётся актуальным, если
  понадобится закрытый доступ и видео.
- История git растёт на каждой переозвучке: 76 МБ mp3 — это нормально разово,
  но каждая пересборка аудио добавляет в историю новую копию файла навсегда.

## 11. Что дальше

**Ближайшее:** озвучка фраз наизусть с транскрипцией и разбором произношения
(раздел 6а) сделана во всех тридцати уроках. В подготовительных уроках таблицы
«Выучить наизусть» нет, поэтому они сюда не входят. Осталось послушать
и вычитать: 320 разборов писались руками, и владелец их ещё не смотрел.

**Контрольные работы (раздел 6б):** собраны все шесть, после уроков 5, 10, 15,
20, 25 и 30. Владелец их ещё не смотрел — это следующее, что стоит вычитать
и прослушать вместе с разборами фраз.

**Сборка уроков:** все уроки собраны. Бонус (карточки Anki к сериалу Nicos Weg)
владелец делать не просил и убрал из списка на главной — папка `36 Бонус…`
остаётся неиспользованной. В `build.py` бонус не попадает в `items`, поэтому
ни в `lessons.json`, ни на главной странице его нет.
На каждый урок уходит один проход по шагам раздела 7.

**Чего в материалах нет и что мы добавляем сами** (из фраз урока, с пометкой
владельцу): диктант, письменное задание с образцом, устное задание с образцом.

**Сайт уже онлайн** на GitHub Pages — как это устроено и как выкатывать
изменения, написано в разделе 10.

**Если понадобится закрытый доступ и видео — VPS.** План: Hetzner CX22 (~4,5 €/мес, 40 ГБ), nginx с поддержкой
Range-запросов для видео, TLS, **basic auth и `noindex`** — материалы курса
чужие, сайт должен быть личным кабинетом, а не публичным ресурсом. Деплой
через rsync. Сейчас в страницах уже стоит `<meta name="robots" content="noindex, nofollow">`.

**Идея на будущее:** сейчас страницы уроков — это HTML, который правится руками.
Если уроков станет много и захочется поменять общую структуру, стоит вынести
тело урока в разметку (Markdown или JSON) и генерировать HTML целиком, как
уже делается со словарём.
